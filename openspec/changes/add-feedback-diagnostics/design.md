## Context

设置存储在共享 plist 和主应用 UserDefaults 中；QuickLook 扩展读取共享偏好。当前只有现值，且缺乏写入来源。现有帮助菜单打开 Issues 列表，仓库已有 Bug Report 和 Feature Request 表单。

## Decisions

### 范围和事件格式

- 记录全部设置面板的持久化选项：外观、语言、字体大小、代码主题、Mermaid、KaTeX、Emoji、Typst、引用折叠、行号和 Finder 字体大小；主题工具栏切换复用同一记录路径。
- 记录设置变化，不记录每次点击。相同值不产生事件；滑块连续拖动合并为一次最终变化。旧值使用实际生效值，保留是否来自默认值的信息。
- 事件包含 schemaVersion、事件 ID、UTC 时间、会话 ID、应用版本、字段、旧/新值和来源。来源区分 settings、toolbar、migration、external-observed；外部变化只能说明“观察到”，不猜测操作者或真实修改时间。
- 当前架构不支持可靠取得外部写入者身份，也不能仅凭设置记录重放 Markdown 文档或保证完整复现。

### 本地存储与可靠性

- 主应用是唯一写入者，扩展不新增历史写入或权限。历史独立于共享偏好文件，保存于应用支持目录，使用串行队列和原子写入。
- 保存最近 7 天、最多 200 条事件，以及最近 7 天、最多 20 条启动快照；启动及写入时裁剪。文件总大小限制 256 KiB，必要时淘汰最旧数据。使用用户私有文件权限。
- 操作事件在非主线程落盘，正常退出及反馈导出前刷新待写事件。存储损坏或不可写不影响正常设置，报告标记历史不可用/不完整，不静默伪造空历史。异常终止前尚未落盘的事件可能缺失。
- 启动快照及运行中观察与上次已知状态比较，可记录程序之外发生的变化。首次启动只有基线，不能把已有值标成用户操作。
- 旧偏好迁移单独记录来源；避免应用自己的写入又被重复识别为外部变化。

### 诊断摘要

- 包含应用发布/开发显示版本、build、macOS 版本/build、CPU 架构、当前设置白名单快照、近期事件、启动环境变化和生成时间。
- 语言诊断包含全局首选语言、应用域 AppleLanguages、有效语言偏好、Bundle 支持/首选本地化及实际激活语言。读取这些字段不修改语言配置。
- 仅序列化允许的字段和合法类型/枚举值；异常字符串仅报告“无效值”，不透传可能含路径或私密数据的配置值。
- 不调用 UserDefaults 全量导出，不读取文档内容，不打包原始日志。用户可清空诊断历史；清空不修改实际设置。

### 用户反馈流程

- 保留已有“报告问题”名称，点击后进入本地诊断预览，可编辑报告、取消包含诊断、复制或保存 Markdown 文件；说明继续后摘要会传给 GitHub，最终 Issue 内容公开。
- 继续后打开 `/issues/new?template=bug_report.yml`，预填版本和新增的 `diagnostics` 字段。使用 URLComponents 编码并按编码后字节数控制长度：URL 超过 6000 字节时缩减最旧事件并标注摘要省略条数，完整报告仍可复制/保存；最小摘要仍超限则打开无诊断预填的表单并提供复制操作。
- 6000 字节是本项目的保守策略，不是 GitHub 声明的硬限制。首次发布须实际验证浏览器和 GitHub 表单预填。
- GitHub 表单字段 `id` 支持 URL 预填，依据 [GitHub 官方 schema 文档](https://docs.github.com/en/communities/using-templates-to-encourage-useful-issues-and-pull-requests/syntax-for-githubs-form-schema)。不假定可以通过 URL 自动上传文件附件。
- “建议新功能…”直接打开 `feature_request.yml`。更新 Bug 模板的系统版本选项，支持 macOS 27 和自由补充系统 build。
- 没有网络或浏览器打开失败时，保留预览并提供复制/导出。缺少 GitHub 登录不阻塞本地生成报告。

## Validation

先编写失败测试，再实施。测试设置覆盖、来源区分、无变化去重、滑块合并、重启持久化、裁剪、损坏/写入失败、迁移与外部变化、白名单及恶意字符串过滤、中文 URL 编码、超长降级、清空及禁用诊断。最后构建并验证主应用 UI、GitHub 表单预填及 QuickLook 仍能读取设置。
