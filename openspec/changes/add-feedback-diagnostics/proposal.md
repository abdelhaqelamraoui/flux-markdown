# Change: 记录近期设置变化并生成反馈诊断信息

## Why

macOS 升级后出现界面语言异常时，只能看到当前偏好为德语，无法确定它来自用户操作、迁移还是外部修改。需要保存近期设置变化和环境快照，让用户报告 Bug 时自动带上可供分析的上下文。

## What Changes

- 在本地保存最近 200 条设置变化，不按时间过期：时间、设置项、旧值、新值、来源、应用版本及进程会话。
- 覆盖设置面板全部持久化选项和文档工具栏的主题切换；记录旧偏好迁移及检测到的外部变化，明确区分观察结果与用户操作。
- 启动时记录系统/应用版本和语言解析快照，帮助识别升级前后环境变化。
- “报告问题…”打开原生反馈预览，自动生成可编辑的诊断摘要，支持复制和导出，再打开预填的 GitHub Bug Report 表单。
- 增加独立“建议新功能…”入口，打开现有 Feature Request 表单。
- 历史仅本地保存；Bug 报告默认包含诊断信息，用户可以预览、移除并清空本地记录。新特性反馈默认不附带设置历史。
- 使用明确字段白名单，不采集 Markdown 内容、文件名、路径、用户名、文档滚动历史或原始系统日志。
- 历史不能补录本次事件；随新版本启用后开始采集。

## Impact

- Affected specs: 新增 `feedback-diagnostics`；现有 `add-settings-ui` 提案已完成，不修改其内容。
- Affected code: `AppearancePreference`、`SharedPreferenceStore` 迁移路径、`LocalizationManager`、主应用启动和帮助菜单、新增历史存储/诊断报告/反馈视图、五套本地化资源、GitHub Bug 表单及用户文档。
- 不新增服务端或 GitHub Token；用户在 GitHub 页面最终提交。
- 当前仅有菜单跳转和两类 GitHub 表单，没有设置历史或自动诊断附件。

## Review status

用户已明确批准实施，并确认取消时间过期策略。实现和本地验证已完成；新增 GitHub 诊断字段的线上验证需在表单合入默认分支后执行。
