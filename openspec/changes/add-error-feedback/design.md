# 报错现场反馈设计

## 重审结论与交互契约

上一版有三处偏离要求：只概括“给出补救”但没有动作优先级；把“一键反馈”退化为打开下一层必经编辑界面；仍要求用户填写软件已知的信息。本版以两项可检查的结果为准：**用户知道并能直接执行下一步；用户不做诊断准备工作也能发起一份可分析的反馈。**

### 报错先服务于当前任务

默认结构为短标题、一至两句指导、一个推荐恢复动作和一个次要反馈动作。是否需要关闭按钮取决于原有界面形态。长说明与技术详情折叠；不能要求用户先读日志才能操作。错误原因未知时只描述已知影响，不能猜测权限、网络或用户操作有误。

更新失败的首屏示例：

```text
更新未完成
你可以手动安装最新版，继续使用 FluxMarkdown。

[下载最新版]  [反馈此问题]  [关闭]
▸ 如何安装       ▸ 反馈内容与技术详情
将打开 GitHub，附带本次错误和系统信息；由你确认发布。
```

“如何安装”展开后显示：下载并打开 FluxMarkdown.dmg，退出 FluxMarkdown，将应用拖入“应用程序”并替换旧版。“反馈内容与技术详情”可查看报告，选择不附诊断，或补充说明；这些是可选能力，不是默认路径的必经步骤。未确认安装状态时不声称原版本一定完整或替换一定解决所有问题。

| 情况 | 首屏指导与主操作 | 反馈的地位 |
| --- | --- | --- |
| 安装器更新失败 | 告知可手动安装；直接打开官方下载页 | 同一界面可一键发起 |
| 文件暂时无法重载 | 告知当前显示的仍是上次内容（仅在确认有保留时）；提供重试/重新选择文件 | 不要求用户丢弃当前阅读进度 |
| 导出目录不可写 | 指导选择其他保存位置；主操作重新打开保存面板 | 不要求用户理解错误码或重跑整个流程 |
| Quick Look 无法呈现完整文档 | 说明限制并直接“用 FluxMarkdown 打开” | 轻量次要入口，不抢占继续阅读 |
| 图表语法/正则校验错误 | 说明可以如何修正或查看源内容；无法自动修正时给可执行替代操作 | 行内反馈，不自动断言这是产品缺陷 |
| 暂时无可行补救 | 如实说明影响，保留已有内容；可将反馈提升为主操作 | 不提供无效重试，也不只留下关闭 |

### 反馈默认一步直达

1. 错误发生时捕获并关联本次上下文，显示错误前已准备最小可用报告。
2. 用户点击“反馈此问题”，软件自动补齐相关安全诊断、保留本地草稿并直接打开预填 GitHub 表单。补充检查异步、有时间上限；不足的信息标为“未获取”，不延迟或阻断最小报告。
3. 已登录用户可以直接确认发布；未登录时遵循 GitHub 登录流程。问题摘要、类别、应用版本、系统信息等已知字段无需用户再填。复现步骤、预期行为、最小样例仅是可选补充；自动说明只写实际观察到的操作，不能编造复现步骤。
4. 使用中立状态“已打开 GitHub，请确认发布”，并保留“再次打开/复制报告”的可达入口。不把打开网页、生成草稿、点击按钮当作提交成功。

这条路径是“一键发起反馈”，不是“点击即发送”。当前项目已有 GitHub 渠道，默认沿用；用户点击后的预填 URL 已将内容发送给 GitHub，因此不能宣称在最终发布前数据始终只在本地。按钮附近先用一句话交代接收方和附带信息，用户可在点击前展开检查/排除诊断。主应用“帮助 → 报告问题”仍可用于没有具体错误事件的手动报告，不作为错误现场反馈的中转站。

如果产品要求点击后直接收到“已接收”的回执，需要新增接收端、认证/滥用控制、保留与删除策略、幂等标识和可查询的接收结果。客户端只有拿到该端的确认才能说“已发送”。这一选项不混入当前 GitHub 方案，也不在本轮设计修订中擅自引入服务。

### 统一机制，按场景呈现

各报错点仅提供稳定的错误分类、上下文和适用恢复动作。统一组件负责本地化表达、反馈数据、动作执行、接收方提示与失败降级；原生对话框、提示条和文档内错误区分别适配当前场景。相同故障在同一操作中合并，多个错误块可共享一个可访问的入口并携带所选块的事件。技术实现、数据保留上限和诊断分类不占用错误首屏。

主要验收不是“增加了按钮”，而是：新用户能看懂并执行一个有效下一步；从错误现场一次点击就能进入已填好必要字段的反馈渠道；失败时不用从头来过。

## 覆盖清单

以下为基于现有源码的接入清单；实现中须逐项记录验证结果。日志字符串搜索只是发现工具，不能作为“所有界面已覆盖”的唯一证据。

| 界面/操作 | 当前入口 | 接入方式与验收重点 |
| --- | --- | --- |
| 自动更新/检查失败 | `AppUpdaterController.swift` | 在下载、关闭之外增加报告操作；先结束原错误 modal，再执行反馈路由，正确确认 Sparkle 错误一次；更新错误在点击反馈前记录，不能依赖稍后才发生的 abort 回调 |
| 文件打开、读取、编码、大小限制 | `MarkdownDocument.swift`、主应用文件入口 | 在可捕获的读文件失败处展示应用自有补救界面或配套反馈入口；验证系统托管错误的实际可接入边界，不全局替换 AppKit 弹窗 |
| 文档重新载入失败 | `MarkdownWebView.swift`、`MarkdownApp.swift`、预览控制器 | 错误提示条可反馈且足够停留；保留重试，不把成功 toast 变成反馈入口 |
| HTML/PDF 导出失败 | `MarkdownWebView.swift` | 对用户操作造成的失败补齐可见提示及反馈；取消保存/打印不作为故障；不记录目标路径或导出内容 |
| WebView 导航、资源缺失、握手超时、进程终止 | 主应用 WebView、预览控制器 | 错误页/原生错误区均有补救和反馈；JS 完全不可用时原生按钮仍可点击；重试不丢弃当前文档 |
| 本地图片不可读、预览受限 | 预览控制器、资源处理器 | 保留“使用主应用打开”；错误/异常限制说明提供反馈入口，报告分类区分已知限制和未预期故障，不上传图片/路径 |
| Quick Look 修复、自检失败 | `QuickLookRegistration.swift`、`QuickLookSelfTest.swift` | 使用相同上下文；仅在相应操作失败时附对应结果；注册成功不能报告成实际渲染成功 |
| 搜索启动、外部编辑器/链接/浏览器打开失败 | WebView、预览控制器、`GitHubStar.swift` | 保留可执行的替代操作和复制固定链接；报告不包含任意文档链接或私人目标 |
| 文档/源码整体渲染错误 | `web-renderer/src/index.ts` | 错误区加语义按钮，通过受控桥接反馈，保留源内容供本地查看但默认不进入报告 |
| Mermaid、Typst、GraphViz、Vega、数学错误显示 | 渲染器对应模块/插件 | 所有实际产生的错误区或错误元素提供反馈入口；语法问题先给修改输入的指导，不能直接断言产品缺陷；不自动附图表/公式源 |
| 搜索正则等输入校验 | `search-ui.ts` 等 | 行内修正指导和低干扰反馈入口；用户编辑输入后恢复正常，取消操作不生成错误记录 |
| 反馈自身的浏览器/保存失败 | `FeedbackView.swift` | 保留已有报告和用户编辑，明确复制/保存替代方式；不再嵌套打开另一份反馈 |
| CLI 导出失败 | `CLIExporter.swift` | stderr 给出补救、固定反馈地址及如何取得安全诊断；无交互命令不弹 GUI |
| 系统托管窗口、Finder 未选中扩展、进程已崩溃 | 产品控制范围外 | 记录能实际观察到的状态；用主应用帮助菜单/后续启动反馈，明确缺失现场，不伪造发生原因 |

## 统一错误上下文

- `ErrorContext` 使用本地事件 UUID、时间、来源组件、操作及阶段的固定枚举、稳定错误分类、安全原因分类、最多八层白名单 NSError domain/code；可附本应用打包代码的固定调用点 ID/模块版本和构建标识以辅助定位，不能将任意异常文本当作可信字段。
- 报错发生时立即捕获来源 app/扩展版本、OS/build/架构、相关白名单设置和有限运行状态。报告明确区分错误快照、当前主应用环境和反馈时采集的补充检查。
- JS 仅发送固定错误分类、已登记操作和阶段；Swift 校验 schema、长度、类型、当前文档代际和来源。异常原文、stack、源码、DOM、URL、搜索词一律不进入自动报告。
- 为错误前后的操作保留有界结构化事件，例如“开始渲染、模块加载、超时、准备导出”；记录状态与结果，不抓取原始 Console/system log。与主错误关联的事件优先进入预填摘要。
- 新诊断记录按每进程/来源最多 100 条、序列化最多 64 KiB 保留，不按时间过期；旧记录按数量/大小移除。现有设置历史仍为 200 条、20 次启动、256 KiB，不改变其策略。
- 主应用负责持久写入自己的诊断存储；扩展内存记录在用户点击反馈后，经受控交接进入主应用。不能承诺扩展在交接前被终止时仍保存全部现场。
- 日志/持久化写入失败不能使原操作再次失败；预览明确显示信息不完整。已有更新错误记录逐步归并，保持升级兼容，不重复记录同一事件。

## 自动收集与用户补充

| 信息 | 收集策略 |
| --- | --- |
| app/扩展版本、macOS 版本/build、架构、语言 | 自动白名单快照，并注明发生时/反馈时 |
| 相关设置、已有设置变化与启动历史 | 复用现有过滤与有界存储 |
| 本次错误码、组件、操作阶段、有限前后事件 | 自动结构化记录；不复制任意异常描述 |
| Quick Look 注册/启用、自检结果 | 按相关组件采集有界只读检查；标记时间/版本，避免把旧自检当新证据 |
| 复现步骤、预期行为、安装方式 | 已知可信信息自动填入，未知项标为“未获取”，可选补充，不阻碍提交；不猜测 Homebrew/DMG 安装来源 |
| 文档、文件路径、图表源、搜索词、截图、原始系统日志 | 不自动采集；确有需要时明确告诉用户如何提供最小非私密样例 |

## Quick Look 与主应用交接

- 复用现有 SearchLauncher 的用户/签名/可执行路径验证，新增固定 `reportError` 操作；不接受任意目标网址、shell 命令或文件读取请求，不扩大沙箱权限。
- 仅用户点击时发送经过 schema/白名单验证、大小不超过 16 KiB 的错误摘要；扩展和代理两端校验，主应用再次验证。传入 payload 的任何字段都不能成为读取私人文件的路径。
- 代理将事件交给所属安装包主应用的统一反馈路由，后者直接打开预填 GitHub 表单。主应用承接过程不弹出必经编辑窗口；接收失败才展示本地降级。交接的是诊断数据或受控引用，不通过本地 URL 传递私人错误文本，不误打开其他开发副本。
- 主应用已开着其他反馈草稿时保留草稿；新事件独立保留上下文并进入自己的预填表单。用户主动展开报告编辑时才展示该事件，不覆盖其他草稿。
- 超时、拒绝或主应用不可用时，在原生错误区显示可复制的安全摘要和“打开 FluxMarkdown → 帮助 → 报告问题”指导。渲染器崩溃不影响此入口。

## GitHub 预填与报告层次

新增面向应用自动反馈的 `app_error.yml` 表单，保留手动 `bug_report.yml` 入口。自动表单仅要求可预填的标题和问题摘要；诊断和补充说明可选，组件/系统分类从事件摘要取得，不要求用户再次选择下拉框。使用 GitHub [官方支持的文本字段预填](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/creating-an-issue#creating-an-issue-from-a-url-query)；模板发布到默认分支后，实际验证“登录后无需补填必填项即可提交”的路径，不能仅凭 URL 单元测试宣称端到端已通过。

实施时已在实际 GitHub 登录会话验证通用 `title`/`body` 预填可直接打开完整报告编辑页，且无需补填分类/系统字段。因此运行时默认使用这一兼容路径，不依赖尚未发布的模板；保留专用模板及其 URL 生成能力，日后切换模板路径前再完成默认分支验证。用户仍只需从报错处点击一次。

首段摘要按“未完成的任务 → 已观察到的失败阶段 → 可确认的触发操作”生成；紧接本次事件的版本、时间和安全错误链。只附与本次故障有关的诊断：更新错误不无条件运行完整 Quick Look 检查，语法错误不采集所有设置。完整本地报告可保留其他相关历史，按需查看。

GitHub URL 超过 6000 字节时优先移除旧历史，保留主错误、关键环境和稳定事件 ID；显示省略提示。诊断排除选择同时作用于本地可见报告和发往 GitHub 的诊断字段。只有用户自行增加的说明会按其预览内容传递；不把当前 Markdown 内容当作自动说明。

## 反馈系统的降级

反馈数据在本地准备，不依赖网络或 JS。诊断采集的失败/超时不会阻止基本反馈，异步补充不会改写已经发往网页的快照或用户编辑。客户端只能可靠判断浏览器启动是否被接受，不能据此判断网页加载、登录或发布成功；因此保留同一报告的重开、复制和保存入口，用户看到网络错误时不必重新收集。

原错误界面仍存在时原地展示降级状态；对于已经结束的 Sparkle modal，使用承接同一事件和草稿的反馈面板，并保留下载等恢复动作。这个面板是当前反馈任务的后续状态，不创建新的错误事件或递归弹出“反馈失败的反馈”。

| 状态 | 显示与下一步 |
| --- | --- |
| 正在补充诊断 | 短暂状态；可用现有摘要继续，不要求用户等待无限扫描 |
| 浏览器已接受打开请求 | “已打开 GitHub，请确认发布”；保留报告和重开入口 |
| 浏览器拒绝打开/Quick Look 交接超时 | 在原区域或承接同一事件的面板显示“暂时无法打开反馈页面，可以复制报告稍后提交”；提供复制报告、重试、保存和固定链接 |
| 用户在网页遇到断网/登录问题 | 已保留的本地报告仍可复制/保存/再次打开；不假称客户端已检测到网页失败或已发送 |
| 保存失败 | 保留原报告，提供复制或选择其他位置，不递归创建新反馈 |
| 同一事件连续点击 | 一个准备/打开过程复用同一事件与草稿；完成后由用户显式再次打开，不在重试中制造自动重复提交 |

## AGENTS.md 的长期约束

仓库规则记录两项不可分割的要求，并将其变为新增/修改报错的评审清单：任务影响与指导、可执行恢复动作、现场一次点击的上下文反馈、自动填写已知信息、按需展示技术详情、保护当前工作、如实报告交接/接收状态、反馈失败降级、隐私过滤、本地化与实际入口验证。实现阶段须登记覆盖清单并复用统一组件，不能只在文案中提及“可反馈”却缺少动作。

## 兼容性与验证

- macOS 11 产品最低版本保持不变；验证默认发布工具链，使用较新本地 SDK 的诊断构建不能宣称 macOS 11 发布验证。
- 主应用、扩展和渲染器五种语言的按钮/提示一致；错误区按钮支持键盘和辅助功能。
- 先写失败测试：无必经本地编辑器的一次点击直达、自动表单无重复必填信息、真实更新错误确认与重查、文件/导出故障、renderer bridge 注入恶意字段、扩展交接超时/错误副本、报告长度/重复事件、写盘失败与隐私排除。
- 用测试夹具逐行验收覆盖清单；错误发生在不同文档/多个窗口时不能混用上下文。实际 Release 沙箱下验证 Finder Quick Look 交接，不以主应用/WebKit harness 替代扩展验收。
- 运行原生、renderer 和真实 WebKit 相关测试，检查正式打包签名/权限与 MacPorts 无 Sparkle 构建路径。实现结束再报告“已覆盖”的具体范围与无法接管的系统界面。
