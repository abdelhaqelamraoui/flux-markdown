# 报错现场反馈设计

## 用户流程

报错界面显示“发生了什么、如何补救”和“报告此问题”。点击反馈按钮，打开已有的本地报告预览，自动填好问题类别、发生时间和诊断摘要。用户可以直接继续到预填的 GitHub 表单，也可以补充说明、移除诊断、复制、保存或取消。最终提交仍在 GitHub 完成。

“一键”指一键准备反馈，不代表未经预览就公开上传。现有 GitHub 账号要求、公开可见提示和 URL 长度限制继续适用。打开网页不能显示成“已提交”。

## 覆盖清单

以下为基于现有源码的接入清单；实现中须逐项记录验证结果。日志字符串搜索只是发现工具，不能作为“所有界面已覆盖”的唯一证据。

| 界面/操作 | 当前入口 | 接入方式与验收重点 |
| --- | --- | --- |
| 自动更新/检查失败 | `AppUpdaterController.swift` | 在下载、关闭之外增加报告操作；先结束原错误 modal，再打开反馈，正确确认 Sparkle 错误一次；更新错误在预览打开前记录，不能依赖稍后才发生的 abort 回调 |
| 文件打开、读取、编码、大小限制 | `MarkdownDocument.swift`、主应用文件入口 | 在可捕获的读文件失败处展示应用自有补救界面或配套反馈入口；验证系统托管错误的实际可接入边界，不全局替换 AppKit 弹窗 |
| 文档重新载入失败 | `MarkdownWebView.swift`、`MarkdownApp.swift`、预览控制器 | 错误提示条可反馈且足够停留；保留重试，不把成功 toast 变成反馈入口 |
| HTML/PDF 导出失败 | `MarkdownWebView.swift` | 对用户操作造成的失败补齐可见提示及反馈；取消保存/打印不作为故障；不记录目标路径或导出内容 |
| WebView 导航、资源缺失、握手超时、进程终止 | 主应用 WebView、预览控制器 | 错误页/原生错误区均有补救和反馈；JS 完全不可用时原生按钮仍可点击；重试不丢弃当前文档 |
| 本地图片不可读、预览受限 | 预览控制器、资源处理器 | 保留“使用主应用打开”；错误/异常限制说明提供反馈入口，报告分类区分已知限制和未预期故障，不上传图片/路径 |
| Quick Look 修复、自检失败 | `QuickLookRegistration.swift`、`QuickLookSelfTest.swift` | 使用相同上下文；仅在相应操作失败时附对应结果；注册成功不能报告成实际渲染成功 |
| 搜索启动、外部编辑器/链接/浏览器打开失败 | WebView、预览控制器、`GitHubStar.swift` | 保留可执行的替代操作和复制固定链接；报告不包含任意文档链接或私人目标 |
| 文档/源码整体渲染错误 | `web-renderer/src/index.ts` | 错误区加语义按钮，通过受控桥接反馈，保留源内容供本地查看但默认不进入报告 |
| Mermaid、Typst、GraphViz、Vega、数学错误显示 | 渲染器对应模块/插件 | 所有实际产生的错误区或错误元素提供反馈入口；语法问题先给修改输入的指导，不能直接断言产品缺陷；不自动附图表/公式源 |
| 搜索正则等输入校验 | `search-ui.ts` 等 | 行内修正指导和低干扰反馈入口；用户编辑输入后恢复正常，取消操作不生成错误记录 |
| 反馈自身的浏览器/保存失败 | `FeedbackView.swift` | 保留已有报告和用户编辑，明确复制/保存替代方式；不再嵌套打开另一份反馈 |
| CLI 导出失败 | `CLIExporter.swift` | stderr 给出补救、固定反馈地址及如何取得安全诊断；无交互命令不弹 GUI |
| 系统托管窗口、Finder 未选中扩展、进程已崩溃 | 产品控制范围外 | 记录能实际观察到的状态；用主应用帮助菜单/后续启动反馈，明确缺失现场，不伪造发生原因 |

## 统一错误上下文

- `ErrorContext` 使用本地事件 UUID、时间、来源组件、操作及阶段的固定枚举、稳定错误分类、最多八层白名单 NSError domain/code；不能将任意字符串当作可信字段。
- 报错发生时立即捕获来源 app/扩展版本、OS/build/架构、相关白名单设置和有限运行状态。报告明确区分错误快照、当前主应用环境和反馈时采集的补充检查。
- JS 仅发送固定错误分类、已登记操作和阶段；Swift 校验 schema、长度、类型、当前文档代际和来源。异常原文、stack、源码、DOM、URL、搜索词一律不进入自动报告。
- 为错误前后的操作保留有界结构化事件，例如“开始渲染、模块加载、超时、准备导出”；记录状态与结果，不抓取原始 Console/system log。与主错误关联的事件优先进入预填摘要。
- 新诊断记录按每进程/来源最多 100 条、序列化最多 64 KiB 保留，不按时间过期；旧记录按数量/大小移除。现有设置历史仍为 200 条、20 次启动、256 KiB，不改变其策略。
- 主应用负责持久写入自己的诊断存储；扩展内存记录在用户点击反馈后，经受控交接进入主应用。不能承诺扩展在交接前被终止时仍保存全部现场。
- 日志/持久化写入失败不能使原操作再次失败；预览明确显示信息不完整。已有更新错误记录逐步归并，保持升级兼容，不重复记录同一事件。

## 自动收集与用户补充

| 信息 | 收集策略 |
| --- | --- |
| app/扩展版本、macOS 版本/build、架构、语言 | 自动白名单快照，并注明发生时/反馈时 |
| 相关设置、已有设置变化与启动历史 | 复用现有过滤与有界存储 |
| 本次错误码、组件、操作阶段、有限前后事件 | 自动结构化记录；不复制任意异常描述 |
| Quick Look 注册/启用、自检结果 | 按相关组件采集有界只读检查；标记时间/版本，避免把旧自检当新证据 |
| 复现步骤、预期行为、安装方式 | 已知可信信息可预填，未知项请用户补充，不猜测 Homebrew/DMG 安装来源 |
| 文档、文件路径、图表源、搜索词、截图、原始系统日志 | 不自动采集；确有需要时明确告诉用户如何提供最小非私密样例 |

## Quick Look 与主应用交接

- 复用现有 SearchLauncher 的用户/签名/可执行路径验证，新增固定 `openFeedback` 操作；不接受任意目标网址、shell 命令或文件读取请求，不扩大沙箱权限。
- 仅用户点击时发送经过 schema/白名单验证、大小不超过 16 KiB 的错误摘要；扩展和代理两端校验，主应用再次验证。传入 payload 的任何字段都不能成为读取私人文件的路径。
- 代理只打开所属安装包的主应用反馈入口。交接的是诊断数据或受控引用，不通过 URL 传递私人错误文本，不误打开其他开发副本。
- 主应用已开着其他反馈草稿时保留草稿，单独展示本次事件或提示用户切换；不得覆盖已编辑报告。
- 超时、拒绝或主应用不可用时，在原生错误区显示可复制的安全摘要和“打开 FluxMarkdown → 帮助 → 报告问题”指导。渲染器崩溃不影响此入口。

## 反馈系统的降级

反馈入口不依赖网络或 JS。报告在本地准备，异步检查有超时且不会覆盖用户编辑。GitHub URL 超过 6000 字节时，优先保留本次错误与关键环境，再剪裁历史并说明省略；完整报告可复制/保存。无法打开浏览器时给出固定问题页面地址和复制报告操作。保存失败时保留原报告并提供复制，不递归创建错误反馈窗口。

## 兼容性与验证

- macOS 11 产品最低版本保持不变；验证默认发布工具链，使用较新本地 SDK 的诊断构建不能宣称 macOS 11 发布验证。
- 主应用、扩展和渲染器五种语言的按钮/提示一致；错误区按钮支持键盘和辅助功能。
- 先写失败测试：真实更新错误确认与重查、文件/导出故障、renderer bridge 注入恶意字段、扩展交接超时/错误副本、报告长度/重复事件、写盘失败与隐私排除。
- 用测试夹具逐行验收覆盖清单；错误发生在不同文档/多个窗口时不能混用上下文。实际 Release 沙箱下验证 Finder Quick Look 交接，不以主应用/WebKit harness 替代扩展验收。
- 运行原生、renderer 和真实 WebKit 相关测试，检查正式打包签名/权限与 MacPorts 无 Sparkle 构建路径。实现结束再报告“已覆盖”的具体范围与无法接管的系统界面。
