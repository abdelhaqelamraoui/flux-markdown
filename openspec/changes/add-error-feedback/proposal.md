# Change: 为报错界面提供一键反馈和自动诊断

## Why

用户遇到问题时，不应再自行寻找反馈入口、复制报错和猜测该收集哪些信息。现有反馈窗口能生成环境与设置报告，但没有覆盖报错现场；部分错误只写日志，Quick Look 和渲染器也没有携带上下文的统一反馈入口。

## What Changes

- 所有应用可控制的错误界面提供“报告此问题”，保留针对任务的补救操作和清晰说明；轻量错误使用行内入口，不新增重复弹窗。
- 点击一次即打开已准备好的本地反馈预览，自动附带本次错误和必要诊断；用户可编辑、移除、复制、保存，再前往 GitHub 自行提交。
- 建立统一错误上下文与有界结构化诊断记录：错误编号、组件、操作、阶段、时间、错误码链，以及发生时的版本和设置快照。后续环境检查与错误发生时的快照分开标记。
- 覆盖主应用、Quick Look、本机错误提示和 Web 渲染器；渲染器未加载时仍提供原生反馈入口。Quick Look 通过已有受控启动代理转交主应用反馈预览。
- 反馈系统本身失败时提供复制/保存的降级方式，避免递归报错；关闭更新失败提示后仍可再次检查更新。
- 自动诊断仅使用字段白名单，不收集文档正文、代码/图表源、搜索词、截图、私人路径、用户名、任意异常文本或原始系统日志。
- 五种语言、本地化补救说明、键盘操作和辅助功能均纳入验收。CLI 提供反馈地址和诊断导出指导，不弹 GUI。

## Impact

- Affected specs: 新增 `error-feedback`；复用已批准实现的 `add-feedback-diagnostics` 和现有 `project-support`，不改变现有设置历史保留策略。
- Affected code: `Sources/Shared/FeedbackDiagnostics.swift`、新的错误上下文/诊断存储、`FeedbackView.swift`、`AppUpdaterController.swift`、主应用文件/渲染/导出路径、Quick Look 控制器及受控启动代理、Web 渲染器错误展示和桥接、五套本地化、用户文档与相关测试。
- 不新增服务端、GitHub Token、自动上传或自动提交。网页加载成功不等于报告提交成功。
- 覆盖清单、数据模型、跨进程交接、降级方式和验收边界见 `design.md`。
- 操作系统/其他程序生成的窗口、扩展未被调用时的 Finder 回退、进程崩溃后不存在的错误窗口无法直接添加按钮；对此保留主应用帮助菜单/下次启动反馈与可验证诊断，不承诺捕获从未执行的代码或追溯旧版本事件。
