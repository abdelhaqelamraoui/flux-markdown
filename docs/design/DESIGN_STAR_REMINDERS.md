# GitHub Star 主动提醒方案

状态：已按用户确认方案实现并完成本机验收。2026-10-12。

## 产品选择

采用按使用情况触发的应用内提醒：达到时间条件后，在下一次合适的使用机会展示。应用退出时不启动、不发送系统通知、不自动打开浏览器。提醒默认启用，可永久关闭；现有手动 Star 入口始终保留。

首版范围为主 App。QuickLook 保留功能指南中的主动支持入口，不弹提醒，也不计入首版使用天数。短暂预览不适合中断；当前主 App 可写、扩展只读共享偏好的结构也不适合直接实现跨进程频率计数。若以后覆盖仅用 QuickLook 的用户，另行设计可写状态协调和去重，不扩大本次权限范围。

参考 [Apple 评分交互建议](https://developer.apple.com/design/human-interface-guidelines/ratings-and-reviews)：用户体验到价值后再邀请，避免首次启动和任务中断。这里仅借鉴交互原则，不使用 App Store 评分接口。以下天数和次数是本项目的初始产品参数，并非 Apple 或 GitHub 的规则。

## 触发规则

同时满足以下条件，首次提醒才有资格展示：

- 从本功能首次记录使用开始，经过至少 7 × 24 小时。
- 至少 3 个不同本地日期有有效阅读；每个日期只计一次。有效阅读为主 App 成功渲染文档且窗口前台可见累计至少 30 秒，不记录路径或正文。
- 用户未停止提醒；总展示次数不设上限。

资格达到后，只在后续文档成功打开、窗口前台稳定 30 秒后检查展示。搜索、文本选择、源码模式、导出、弹窗等任务期间不展示；延后到下一次合适的文档打开机会。不在同一份长时间阅读的文档里突然补弹。

第二次最早为上次实际展示后 14 天，第三次及以后每次均为上次实际展示后至少 30 天；每次之间还需至少一个新的有效阅读日期。即最早约第 7、21、51、81、111 天出现，之后持续按 30 天间隔提醒；未使用期间不累计待展示提醒，不追补。升级不重置计数。

计时使用注入时钟便于测试；负时间差不触发，系统时钟跳变不得一次补发多条。阅读持续时间使用单调时钟。记录开始于新版本首次有效运行，不猜测历史安装日期。

## 展示与文案

在主窗口底部放置一张轻量卡片，沿用阅读区的圆角、边框、强调色和深浅主题。不遮住正文：单独占据底部区域，不抢键盘焦点，窄窗口按钮自动换行；同进程多窗口仅当前主窗口可展示一次。

标题：**觉得 FluxMarkdown 好用吗？**
正文：如果它帮你更方便地阅读 Markdown，欢迎在 GitHub 点个 Star，支持项目继续改进。

操作：**☆ 去 GitHub Star**（主按钮）、**以后再说**、**不再提醒**；提供“我已 Star”次级文字操作。关闭按钮与“以后再说”含义一致，Escape 仅在卡片拥有焦点时关闭，不覆盖文档快捷键。没有自动倒计时消失。

- 去 GitHub Star：复用现有浏览器入口，默认浏览器成功接收打开请求后永久停止主动提醒；状态命名 `supportLinkOpened`，不标记为已经点赞。失败则保留卡片，显示错误及复制链接操作，不停止后续提醒。
- 以后再说 / 关闭：隐藏卡片，遵守下次冷却时间。第三次及以后仍按至少 30 天间隔继续提醒，直到满足停止条件。
- 不再提醒：立即永久停止，无二次确认。
- 我已 Star：立即永久停止；这是用户声明，无须登录或验证。
- 从欢迎页、帮助菜单、功能指南主动打开同一 Star 入口成功，也停止主 App 提醒。首版不纳入 QuickLook 成功事件跨进程同步：当前 XPC 服务没有写入主 App 提醒状态的权限，本次不扩大权限。QuickLook 用户可在卡片点“我已 Star”；不会仅因扩展启动请求发出就写成功状态。

在设置中增加“邀请我在 GitHub 支持项目”开关，关闭立即隐藏卡片并停止提醒。重新开启是用户显式选择，可开始新一轮，至少冷却 14 天，仍需既有使用资格；版本升级不能代替用户重启这一轮。

## 实现结构

- `StarReminderPolicy`：纯规则判定，输入时间、使用摘要、冷却期、停止原因、展示次数和当前交互状态。
- 主 App 原生 coordinator：聚合有效阅读、选择窗口、处理一次性展示；主线程先持久化展示次数再挂载卡片，防止多个窗口重复邀请。只有准备挂载到可见窗口时才计展示。
- 本地持久化：首次使用时间、上次有效日期、有效日期计数、上次展示时间、展示次数、新周期冷却截止时间、停止原因及开关。只存使用摘要，不存文件、GitHub 身份或上传统计。
- 停止原因区分 `supportLinkOpened` / `selfReportedStarred` / `optedOut`；不存在“已验证 Star”状态。
- 原生卡片复用 `GitHubStar.openRepository` 的成功/失败结果。QuickLook 的可选事件同步必须沿用可信固定动作服务，独立验收；不引入 OAuth、后台守护进程或提醒通知权限。

## 验收

规则测试覆盖首次启动、第 7 天边界、少于 3 个有效日期、14/30 天冷却、第三次之后持续按 30 天提醒、无总次数上限、用户主动重新开启、时钟回退和跨版本持久化。UI 验证覆盖多窗口去重、后台不展示、忙碌状态延后、深浅主题、窄窗口、VoiceOver、键盘和本地化。

每个按钮测试其停止/延后行为；浏览器失败不得误判支持完成；主 App 所有手动 Star 入口同步停止；QuickLook 不主动提醒。实机测试只验证仓库打开，不替测试账号执行点赞。QuickLook 成功事件跨进程同步不在本轮发布范围内。
