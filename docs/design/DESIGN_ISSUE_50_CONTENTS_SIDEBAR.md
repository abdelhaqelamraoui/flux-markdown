# #50：常驻目录侧栏与顶部阅读工具

状态：2026-10-10 方案细化。本轮交付设计与示意，尚未将下面全部交互实现到产品。

来源：[Issue #50](https://github.com/xykong/flux-markdown/issues/50) 及其评论。
原始诉求是让长文档的目录持续可见且不遮挡正文；附议同时指出浮动按钮太大、挡住内容，希望移到顶部。

## 推荐方案

采用“顶部阅读工具区 + 右侧停靠目录 + 窄窗口按需浮层”。沿用现有右侧入口和共享网页目录，减少学习成本；正文与目录分栏，目录不随正文滚出视野。首版侧栏固定 240 CSS px，不增加拖拽宽度、左右换边、全局设置等额外选项。

### 宽窗口

- App 和展开的 QuickLook 有标题且可用内容视口宽度 ≥900 CSS px 时，默认显示右侧目录。
- 目录宽 240 px，正文栏至少 560 px，其余约 100 px 分配给间距、分隔和正文留白。900 是初始阈值，需用实际字体、缩放与原生窗口验收。
- 判定使用 WebView 实际可用的 CSS 视口宽度，不使用显示器像素宽度或 NSWindow 外框宽度。
- 左边正文，右边目录；边界使用细分隔线，目录底色与正文略有区分，不做悬浮卡片和重阴影。
- 正文最大行宽在正文栏内居中；代码块、表格在各自区域横向滚动，不伸入目录栏。
- 正文滚动仍由现有页面承担，目录独立滚动，避免重做现有行号定位、滚动恢复、搜索和链接跳转。
- 关闭目录立即回收占位；顶部“目录”按钮始终可用于重新打开。

### 顶部阅读工具区

- 把“目录”和现有“折叠引用块”按钮放到同一固定工具区，与现有工具风格、大小对齐。折叠引用块不命名为“折叠目录”，避免功能误解。
- 工具区在文档布局中预留高度，正文及目录从其下方开始。不能只把悬浮按钮的 top 值改小。
- 优先复用现有原生工具栏剩余空间。若 App/QuickLook 无法一致接入，使用共享 renderer 顶部单独一行，并明确与原生工具栏的边界；同一功能只出现一个入口。
- 没有引用块时隐藏折叠引用块按钮；没有标题时隐藏目录按钮和侧栏，并回收对应空白。
- 搜索栏展开时占用工具区下方独立一行，内容起始位置同步下移，不遮住标题或目录。
- 首版不重做其他工具按钮，也不增加全局快捷键。QuickLook 内直接 ⌘F 已由用户取消，沿用按钮打开主应用搜索。

### 窄窗口

- 内容视口 <900 CSS px 时不常驻侧栏，正文使用完整宽度，目录入口保留在顶部。
- 点击目录，弹出右上方临时面板。宽度为 min(280 px, 视口宽度−32 px)，高度不超过工具区下方可见区域；长目录内部滚动。
- 临时浮层会暂时覆盖一部分正文，这是窄窗口中明确的导航状态，不宣称所有场景都零遮挡。
- 点击有效标题后完成跳转并自动收起；点击正文或再次点击目录按钮也收起。
- 主应用中 Esc 优先关闭目录浮层并将焦点交还目录按钮。QuickLook 保留系统 Esc 行为，提供鼠标可达的关闭方式，不依赖捕获按键。
- 从宽变窄时自动关闭临时面板，不因为宽窗口目录原本可见而突然覆盖正文；恢复宽窗口时恢复之前的停靠选择。

### 显隐状态

将“停靠偏好”和“当前浮层是否打开”分开，避免一个布尔值承担两个含义。

| 操作 | 宽窗口停靠 | 窄窗口浮层 |
|---|---|---|
| 新视图有标题 | 自动显示 | 默认关闭 |
| 宽窗口手动关闭 | 保持关闭 | 不自动打开 |
| 宽窗口手动打开 | 保持打开 | 缩窄后收起 |
| 窄窗口点击目录 | 保留原停靠偏好 | 打开/关闭 |
| 窄窗口选择章节或点正文 | 保留原停靠偏好 | 关闭 |
| 窄窗口恢复为宽窗口 | 恢复停靠偏好；自动模式则显示 | 关闭 |
| 同文件重载、主题切换 | 保留偏好 | 内容重建时保留原开闭状态；无标题则关闭 |
| 新开独立文档视图 | 使用默认值 | 使用默认值 |

首版仅记忆当前文档视图会话，不写入跨文档、跨进程或跨次启动偏好。全文标题临时清空时隐藏目录，但保留停靠偏好；标题恢复后按当前宽度重新计算。

## 目录内容和导航

- 展示 H1–H6 层级。以文档最浅标题为基准缩进，不因缺少 H1 而整体空出一级；深层缩进设上限，保留可读宽度。
- 首版沿用完整标题树，不另加目录树的折叠交互。长标题单行截断，悬停和无障碍名称可读取全文。
- 以浅色背景和字重同时标记当前章节；普通滚动时按正文可视区顶部最近的标题更新。没有更浅标题时，高亮最近的前置标题。
- 点击目录跳转时，标题落在所有固定工具区下方。重复标题使用 renderer 已生成的唯一锚点，不重新按标题文本推导。
- 停靠模式点击标题后保持目录打开；浮层模式跳转后关闭。无效锚点保持当前阅读位置，不错误跳到页首。
- 默认只在当前活动项已离开目录可见区域、且用户未主动滚动目录时，最小距离滚动目录；不得持续把用户正在查找的目录拉回。
- 布局切换先记录正文可见块及其相对顶部偏移，布局完成后恢复；不能只恢复旧 scrollY，因为换行会改变内容高度。
- 锚点导航使用平滑滚动，并尊重减少动态效果设置；重载和布局恢复直接定位，避免来回动画。

## 场景边界

| 场景 | 行为 |
|---|---|
| 主应用普通/全屏窗口 | 按实际内容宽度切换，保留显隐选择 |
| 展开的 QuickLook 预览 | 使用相同分栏和点击导航，不强行获取键盘焦点 |
| Finder 紧凑预览栏 | 保留简洁预览，不显示目录和相关工具区占位 |
| 无标题文档 | 隐藏目录入口、面板及占位 |
| 主题/缩放变化 | 对比度可读，重新评估可用布局，保留阅读位置 |
| 打印/PDF/HTML 导出 | 排除全部阅读控件和侧栏占位，正文恢复完整输出宽度 |
| 多个文档同时打开 | 目录、当前章节、显隐选择相互独立 |

键盘可操作性在主应用中验收：Tab 可到达入口和链接，Enter/Space 操作按钮，Enter 激活链接，焦点样式可见。目录入口同步 aria-expanded/aria-controls，活动链接设置 aria-current，所有文案按现有本地化方式处理。QuickLook 的鼠标导航不得依赖键盘输入权限。

## 现有实现差距与落地顺序

目前 `TableOfContents.updateLayout()` 已有 900 px 阈值、右侧 240 px 目录和会话显隐。CSS 通过 body padding-right 给固定定位目录预留位置；按钮仍用多个 top/right 值布局，`userVisibility` 同时影响停靠和浮层。这是可复用的起点，不能视为完整方案已验收。

1. 补充显隐状态转换测试，分离停靠偏好与临时浮层；加入选中关闭、点外部关闭和无标题恢复场景。
2. 建立统一工具区与正文/目录布局，集中计算顶部高度和侧栏占位，移除旧的散落定位覆盖规则。尽量保留现有正文滚动容器。
3. 将目录和引用块按钮接入该工具区，统一尺寸、文案及可见条件；同步搜索栏的布局。
4. 加固活动章节、长标题、重复锚点、滚动恢复与多文档隔离。
5. 完成真实 App/QuickLook 截图、打印及导出验收后，更新用户说明和发布说明。发布后在 #50 说明“常驻目录”和“按钮移位”两项具体变化，按项目规则处理标签与回复。

## 验收清单

- [ ] 宽窗口在连续滚动中目录始终可见；正文、代码、表格不与目录和按钮相交。
- [ ] 899/900/901 CSS px，以及实际 520/760/1100 px 窗口，均符合布局和状态规则。
- [ ] 宽窗口关闭目录 → 缩窄 → 重载 → 恢复宽度，目录仍保持关闭；窄窗口打开浮层不改写停靠偏好。
- [ ] 停靠切换后同一正文块相对顶部偏移在稳定布局后误差 ≤8 CSS px，且不跳到文档顶部。
- [ ] 0、1、100 个标题、H2 起始、深层标题、重复标题、超长标题均可正确导航。
- [ ] 窄浮层点击目标、点正文、主应用 Esc 可关闭；QuickLook 点击可用且不抢键盘焦点。
- [ ] 用户滚动目录时不会被活动项追踪拉回；切换文档不串状态。
- [ ] 搜索栏展开、浅/深色、100%/150%/200% 缩放、普通/全屏均无重叠或入口丢失。
- [ ] Finder 紧凑预览、HTML/PDF/打印无目录控件、空白侧栏或多余顶部占位。
- [ ] 功能和样式两类测试通过；真实应用验收覆盖所有上述关键布局，不能仅依赖 DOM 单元测试。

示意用于确认布局与交互方向，尺寸以实际应用验收为准。
